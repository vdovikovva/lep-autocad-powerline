# CLAUDE.md

Инструкции для Claude Code в этом репозитории.

## Что это за проект

Набор AutoLISP-модулей (`LEP-*.LSP`) для автоматизации черчения ЛЭП
(линий электропередач) в AutoCAD 2025 — трассировка маршрута,
расстановка опор, нарезка пролётов, выгрузка ведомости.

Источник правды по логике работы, текущему состоянию и известным
проблемам — [LEP-README.md](LEP-README.md). Обновляй его при каждом
значимом изменении в модулях.

## Критическое правило хранения файлов

DWG чертежа должен лежать **в той же папке**, что и все модули
`LEP-*.LSP`. На этом держится поиск файлов (`findfile`) и
автоматическая регистрация папки в `TRUSTEDPATHS` внутри
`LEP-START.LSP`. Не перемещай DWG или .LSP-файлы в подпапки и не
меняй эту структуру — иначе загрузка сломается у пользователя на
любой платформе (Mac/Windows).

## Структура модулей

- `LEP-START.LSP` — загрузка всех модулей через Support Path/findfile,
  авторегистрация папки в TRUSTEDPATHS. Точка входа (`APPLOAD`). После
  загрузки всех модулей автоматически вызывает `(C:LEP-SETUP)` — слои
  проекта создаются без отдельной ручной команды (`LEP:CreateLayer`
  безопасен при повторном вызове, ничего не пересоздаёт). Команда
  `LEP-SETUP` больше не значится в списке команд, который печатается
  после загрузки — она не нужна для обычной работы (осталась доступна
  вручную на случай, если слой случайно удалили).
- `LEP-CONFIG.LSP` — все настраиваемые параметры проекта (блок опоры,
  геометрия символа-трапеции, типы проводов/кабелей по классу
  напряжения, режим диалога DCL/консоль и т.д.).
- `LEP-SCALE.LSP` — калибровка масштаба подложки по двум точкам.
- `LEP-ROUTE.LSP` — черчение маршрута (полилиния), присвоение ID
  (`LEP_ROUTE_01`, ... — 2 цифры, см. `LEP:CreateRouteID` в
  LEP-DATA.LSP). Сразу ставит подпись "Маршрут NN" у начальной точки
  (`LEP:CreateRouteLabel`, с 2026-07-15 через `_.MLEADER`, было
  `_.LEADER` — см. README), иначе трассу снаружи не отличить, ID
  виден только в XDATA. Спрашивает класс напряжения маршрута (10кВ/
  0,4кВ, `*LEP-VoltageClasses*`) ОДИН РАЗ на весь маршрут — хранится в
  XDATA (`VCLASS`), используется в `LEP-SPAN` (список марок провода) и
  `LEP-POLE` (вторая строка подписи опоры). Рисуется на служебном слое
  `*LEP-Layer-Route*` (НЕ на слое ВЛ) — команда `LEP-ROUTEVIS` (тоже
  в этом файле) переключает его видимость на экране; печать слоя
  выключена всегда, отдельно от видимости (см. `LEP-SETUP.LSP`).
- `LEP-POLESYM.LSP` — символ опоры (трапеция 1×1м с узкой стороной
  0,7м + крест 1,07м через центр, крест ФИКСИРОВАННО серый —
  `*LEP-Color-PoleCross*`, задан прямо в геометрии блока, группа DXF
  62 — не зависит от цвета/статуса самой опоры). Создаётся автоматически
  из `LEP-START.LSP` через `entmake` (BLOCK/LWPOLYLINE/LINE/ENDBLK) —
  НЕ через интерактивный `-BLOCK`, надёжнее (см. правило про `command`
  ниже). **⚠️ Блок создаётся ТОЛЬКО если его ещё нет** — в отличие от
  слоёв, НЕ передефайнится на каждой загрузке (честный передефайн
  `-BLOCK` не протестирован вживую в консоли). Толщина линии по
  статусу (Проект. жирнее Сущ.) — через `LWEIGHT` (DXF 370) на самом
  `INSERT`, геометрия внутри блока имеет `LWEIGHT = ByBlock`.
  Разворот — по направлению маршрута (широкая сторона к началу трассы,
  узкая к концу). По типу опоры (`*LEP-PoleColumns*`) собирает 1/2/3
  трапеции (главная опора + откос(ы) для анкерных/угловых типов, шаг
  `*LEP-Pole-Sym-Offset*` = 2м) — **⚠️ угол разворота откоса — черновая
  прикидка, не подтверждена**, см. README (раздел с восклицательными
  знаками).
- `LEP-SETUP.LSP` — создаёт все слои проекта с цветами из CONFIG (цвет
  проектируемых опор — оранжевый, `*LEP-Color-Proj-VL*`, был красный —
  совпадал со служебной линией маршрута). Запускается автоматически из
  `LEP-START.LSP`, руками вызывать не нужно (иначе, если бы отдельная
  команда была забыта, `LEP:SetCurrentLayer` не нашёл бы слой и
  промолчал, объект ушёл бы не на тот слой). Последним создаётся слой
  `*LEP-Layer-Manual*` (`LEP-MANUAL`) — СОЗНАТЕЛЬНО последним:
  `-LAYER Make` всегда делает только что созданный слой текущим
  (свойство самой команды AutoCAD, не обойти), поэтому пусть после
  автозапуска текущим остаётся безопасный "черновой" слой, а не
  случайный технический (ВЛ/КЛ/опоры/DIM), куда могла бы случайно
  попасть ручная линия и испортить ведомость. Также создаёт единый
  текстовый стиль проекта (`LEP:CreateTextStyle` — наклонный
  `ISOCPEUR`, угол 10°, высота 1,3, делается текущим и для текста, и
  для размеров `DIMTXSTY`) — см. README для пояснения, почему высота
  у текстового стиля автоматически замещает `DIMTXT` у размерных
  линий. `entmake` для таблицы `STYLE` требует маркеры подкласса
  (`AcDbSymbolTableRecord`/`AcDbTextStyleTableRecord`) - без них
  запись формально создаётся, но `setvar "TEXTSTYLE"` её отклоняет
  ("AutoCAD variable setting rejected"); сам `setvar` для
  `TEXTSTYLE`/`DIMTXSTY` обёрнут в `vl-catch-all-apply`, чтобы сбой
  тут не обрывал остаток `C:LEP-SETUP`. **⚠️ Проверено вживую в
  консоли** (не по памяти): `"ISOCPEUR"` (БЕЗ `.shx`!) на проверенной
  установке — TrueType-шрифт, не SHX-файл (SHX-аналог с похожим видом —
  `"isocp.shx"`, без "eur"); угол наклона (группа DXF 50 у `STYLE`) — в
  РАДИАНАХ, не в градусах, как изначально предполагалось по памяти
  (`*LEP-TextStyle-ObliqueAngle*` в CONFIG хранится в градусах,
  перевод в радианы — в `LEP:CreateTextStyle` перед `entmake`).
  Также настраивает стиль выносок `MLEADER` (`LEP:CreateMLeaderStyle` —
  правит НАПРЯМУЮ стиль "Standard" через `dictsearch`/`entget`/`subst`/
  `entmod`, т.к. `MLEADERSTYLE` не классическая таблица AutoCAD и
  `tblobjname` для него возвращает `nil`) — миграция подписей с
  `LEADER` на `MLEADER` от 2026-07-15, полная история и найденные
  DXF-группы (43/42/44/45/93/174/178/295/298) — в README.
- `LEP-LINETYPES.LIN` — свой тип линии `LEP_CABLE` для КЛ (штамп "К"
  в разрывах), которого нет в стандартном `acad.lin`. Загружается
  через `findfile`, как и всё остальное в проекте.
- `LEP-POLE.LSP` / `LEP-POLE.DCL` — ручная расстановка опор в цикле:
  проекция на трассу, вставка вершины, выбор типа/статуса, вставка
  символа-трапеции (`LEP-POLESYM.LSP`, разворот по маршруту), привязка
  ГЛАВНОЙ трапеции через `GEOMCONSTRAINT` (откосы не привязаны),
  двухстрочная подпись-выноска ("[статус]. оп. [тип]" + класс линии
  маршрута, с 2026-07-15 через `_.MLEADER` + код разрыва абзаца `\P`
  для второй строки, было `_.LEADER` — см. README).
  `LEP:InsertVertexOnRoute` (общая с `LEP-END.LSP`) НЕ
  вставляет вторую вершину, если клик попал в пределах
  `*LEP-Vertex-Snap-Tolerance*` от уже существующей (исправленный баг:
  угловая опора на реальном изломе маршрута создавала вырожденный
  отрезок и роняла `GEOMCONSTRAINT` конфликтом "over-constrain"). После
  каждого `GEOMCONSTRAINT` идёт пустой `(command)` (Escape) — страховка
  на случай, если констрейнт всё же не наложится по другой причине,
  чтобы команда не зависала и не портила остаток цикла. Там же
  `LEP-POLE-ALONE` — та же опора БЕЗ привязки к
  трассе (свободно двигается, без разворота — нет маршрута, от
  которого его считать), но для ведомости автоматически привязывается
  к БЛИЖАЙШЕЙ трассе по ID (`LEP:FindNearestRoute`, теперь возвращает
  ещё и класс напряжения этой трассы для подписи) — **⚠️ известный
  риск неверной привязки на границе территорий двух заявителей, см.
  README** (раздел с восклицательными знаками вверху файла).
- `LEP-END.LSP` — оконечное оборудование маршрута: ПУ (0,4кВ, 1 опора
  `*LEP-End-PoleType*` + подпись "ПУ") или МТП (10кВ, 3 такие же опоры
  подряд, шаг 3м/2м, подписи РЛК/МТП-160 кВА/ЩУ). ОДНА концовка за
  запуск, без цикла (просьба пользователя). РЛК/МТП/ЩУ/ПУ — не
  своя графика, только текстовые подписи. Три подписи МТП разведены в
  разные стороны (`*LEP-End-LabelAngle-RLK*`/`-MTP*`/`-SchU*`) - опоры
  стоят близко (шаг 3м/2м), при одинаковом направлении подписи
  накладывались друг на друга. Первая опора — как в `LEP-POLE`
  (проекция+вершина+`GEOMCONSTRAINT`), опоры 2/3 МТП — дальше ПО УГЛУ
  МАРШРУТА (RouteDir), без проекции. **⚠️ Угол маршрута и угол
  поворота блока (`LEP:GetPoleRotation`) — РАЗНЫЕ углы, отличаются на
  90° — их уже один раз перепутали (опоры МТП уезжали перпендикулярно
  трассе, фикс 2026-07-11), не путать снова.** Тип/статус
  зафиксированы, не спрашиваются.
- `LEP-SPAN.LSP` — классификация пролётов между опорами (клик по
  блокам), выбор ВЛ/КЛ и марки провода/кабеля (список ВЛ зависит от
  класса напряжения маршрута — `*LEP-WireTypes-VL-10*` СИП-3 vs
  `*LEP-WireTypes-VL-04*` СИП-2, это разные провода физически),
  создание отдельного объекта-пролёта со своим слоем/типом линии. Длина материала (не то
  же самое, что расстояние между опорами!) считается с запасом:
  ВЛ +`*LEP-Sag-VL*`% на провис, КЛ +`*LEP-KL-Reserve*` м на подъём
  на опору, округление вверх до метра (`LEP:GetRealLength`) - именно
  это число идёт в подпись и в XDATA `LENGTH`/ведомость (подпись
  пролёта — с 2026-07-15 через `_.MLEADER`, было `_.LEADER` — см.
  README). Отдельно рисуется размерная линия (`LEP:CreateSpanDimension`, слой
  `LEP-DIM`, команда `DIMALIGNED` — параллельно самому пролёту, а не
  всегда горизонтально/вертикально как у `DIMLINEAR`) с прямым
  расстоянием между опорами, округлённым по обычным правилам
  математики. Ориентация текста подписи размера (сейчас поворачивается
  вместе с линией) пока не трогается — сознательно отложено.
- `LEP-REPORT.LSP` — выгрузка ведомости в CSV. Без ActiveX (данные
  берутся из XDATA, не из блока/vla-*). Считает только проектируемые
  (Проект.) объекты, блоками по трассам + сводка "ИТОГО". Опоры
  `LEP-END` считаются дважды: как обычная опора по `MODEL` (уже было),
  и ОТДЕЛЬНОЙ строкой по ключу `EQUIP` (РЛК/МТП/ЩУ/ПУ) — префикс
  "Опора " в CSV теперь добавляется только реальным опорам (проверка
  по `*LEP-PoleTypes*`), а не всему подряд с `Unit="шт."`, иначе
  "РЛК" превращалось бы в "Опора РЛК". CSV в
  UTF-8 с BOM — ключ: `(open path "w" "utf8-bom")`, третий аргумент
  `open` (AutoCAD 2021+). Без него `open` пишет старой однобайтовой
  кодировкой (Windows-1251 для кириллицы); просто `"utf8"` без BOM
  не годится — Excel без метки BOM не определяет UTF-8 сам и
  показывает кракозябры, хотя другие программы открывают верно и без
  неё. Если где-то ещё в проекте понадобится писать файл с
  кириллицей — используй `"utf8-bom"` сразу, не по одной догадке.
- `LEP-DATA.LSP` — хранение данных объектов через XDATA,
  `LEP:GetDataValue` для чтения по ключу. `LEP:AddRoute` теперь пишет
  и класс напряжения (`VCLASS`). `LEP:AddEquipData` — то же, что
  `LEP:AddPoleData`, плюс ключ `EQUIP` для оконечного оборудования.
  Номер нового маршрута берётся из САМОГО ЧЕРТЕЖА
  (`LEP:GetMaxRouteNumber` — max существующих ID + 1), НЕ из счётчика
  в памяти — счётчик сбрасывался при перезапуске AutoCAD и ID
  дублировались, молча сливая два маршрута в один блок ведомости
  (фикс 2026-07-11). `LEP:AddPoleData` принимает статус параметром
  (раньше всегда писала PROJECT, даже для Сущ.).
- `LEP-UTILS.LSP` — общие вспомогательные функции.
- `LEP-POLYLINE.LSP` — работа с полилиниями. Сейчас одна функция,
  `LEP:GetVertices` (список вершин LWPOLYLINE) — общая для ROUTE/
  POLE/SPAN/END, грузится раньше всех.
- `LEP-MAKETESTBLOCK.LSP` — УДАЛЁН ИЗ ПРОЕКТА (2026-07-10). Создавал
  старую заглушку `test-block` (кружок+атрибут) — полностью заменена
  настоящим символом-трапецией (`LEP-POLESYM.LSP`), файл больше не
  нужен даже для отладки (см. историю git, если понадобится).

## Временные решения (см. README для деталей)

- **⚠️ Угол разворота откоса** у 2-/3-столбовых опор (`LEP-POLESYM.LSP`,
  `LEP:InsertPoleGroup`) — черновая прикидка (перпендикулярно маршруту,
  поворот 90° от главной опоры), точный угол уточняется у коллеги
  пользователя. Когда придёт точный угол — поправить ТОЛЬКО эту
  функцию.
- **⚠️ Блок символа опоры не передефайнится** при повторной загрузке
  (в отличие от слоёв) — см. README, раздел с восклицательными
  знаками, если нужно обновить геометрию после правок.
- Объект-пролёт из `LEP-SPAN` НЕ связан через `GEOMCONSTRAINT` с
  опорами — при переносе опоры пролёт придётся перечертить заново.

## Известные открытые проблемы

- Марки СИП-3 в `*LEP-WireTypes-VL-10*` — введены "на правдоподобный
  вид" по референсу пользователя, не сверены с реальным каталогом.
- `*LEP-Label-MTP*` = "МТП-160 кВА" — мощность зашита жёстко в текст,
  не спрашивается. Уточнить, бывает ли другая мощность у заявителей.
- После одного прогона `LEP-SCALE` у пользователя оказались выключены
  два слоя — код-ревью не нашло в проекте механизма, способного это
  сделать (кроме `LEP-ROUTEVIS`/`LEP:FindNearestRoute`, которые трогают
  только слой маршрута). Не воспроизвелось повторно, причина не
  найдена — отложено, см. README для деталей на случай повтора.
- **Отступ перед текстом подписи (`LEADER`) — ✅ РЕШЕНО 2026-07-11**:
  причиной была полка LEADER длиной = размеру стрелки (`DIMASZ`,
  дефолт ISO-25 = 2.5 → 2,5 МЕТРА в масштабе 1 ед. = 1 м). Лечится
  `(setvar "DIMASZ" *LEP-Dim-ArrowSize*)` в `LEP-SETUP` (0,8 в
  CONFIG). `DIMGAP`/шрифт были ни при чём; гипотеза про
  TrueType-рамку опровергнута живым тестом. ⚠️ `isocp.shx` НЕ содержит
  кириллицу — не предлагать SHX-шрифты для русских подписей. Полная
  история — в README. **С 2026-07-15 подписи опор/маршрута/пролёта
  создаются через `MLEADER`, не `LEADER`** (см. отдельную запись ниже) —
  `DIMASZ` больше НЕ отвечает за отступ у подписей, но всё ещё нужен
  для стрелок `DIMALIGNED` (размерная линия пролёта, `LEP-SPAN.LSP`) —
  трогать/убирать нельзя.
- **Миграция подписей `LEADER` → `MLEADER` — ✅ РЕАЛИЗОВАНО 2026-07-15**:
  стрелка+полка+текст теперь один объект, текст лежит на полке/
  подчёркнут (настройка стиля "Standard", `LEP:CreateMLeaderStyle` в
  `LEP-SETUP.LSP`). Найденные живым тестом группы DXF стиля
  `MLEADERSTYLE`: 43=полка, 44=стрелка, 45=высота текста, 42=зазор,
  93=цвет (ByLayer), 174/178/295/298=подчёркивание (⚠️ последние 4 —
  подтверждены только КОМБИНАЦИЕЙ, не по отдельности). Полная история
  тестов и таблица значений — в README, раздел "✅ Миграция подписей
  LEADER → MLEADER". Открыто: размер стрелки 0.8 не сверен визуально
  на реальном чертеже (в отличие от DIMASZ 0.8, который сверяли).
- **Заливка символа опоры (`SOLID`)** — подтверждено рабочим тестом в
  консоли (порядок вершин 1-2-4-3, не по периметру), но НЕ
  интегрирована в `LEP-POLESYM.LSP` — отложено по решению пользователя,
  подход рабочий, можно добавить в любой момент.

## Правила работы с кодом в этом проекте

- **⚠️ ЕСЛИ НЕ УВЕРЕН В ТОЧНОМ ПОВЕДЕНИИ/СИНТАКСИСЕ — СНАЧАЛА ПРОВЕРЬ
  МАЛЕНЬКИЙ КУСОЧЕК ЖИВЬЁМ В КОНСОЛИ AUTOCAD, ПОТОМ ПИШИ В ФАЙЛ.**
  Это касается: точного порядка аргументов `command` (уже ловили баги
  на `LEADER`, `-linetype`), единиц измерения углов (радианы/градусы —
  не одинаково для всех DXF-групп, например у `STYLE` угол наклона в
  градусах, а у большинства остальных entmake-углов в проекте —
  радианы), точной структуры `entmake` для таблиц (`STYLE`/`LAYER` и
  т.п. требуют маркеров подкласса, которых легко не досчитаться),
  доступности шрифтов/ресурсов в конкретной установке AutoCAD. Если
  сам не можешь протестировать (нет живой консоли под рукой) — дай
  пользователю МАЛЕНЬКИЙ, изолированный кусок кода/команду, попроси
  вставить в командную строку AutoCAD и показать результат, и только
  ПОСЛЕ этого пиши финальную версию в файл. Не полагайся на память о
  DXF-документации там, где реальный тест возможен и дёшев — в этом
  проекте это правило уже несколько раз забывалось "в комментариях",
  но не было явно записано здесь, из-за чего нарушалось снова.
- Это AutoLISP (Visual LISP диалект AutoCAD), а не обычный Lisp —
  используются функции `vl-*`, `vla-*` (ActiveX, только Windows) и
  DCL-диалоги. При правках проверяй кроссплатформенность (Mac не
  поддерживает ActiveX).
- Изменения тестируются вручную в AutoCAD через `APPLOAD` —
  автоматических тестов нет. После значимых правок обнови раздел
  "Что уже готово и проверено" / "Известные открытые проблемы" в
  [LEP-README.md](LEP-README.md).
- Не хардкодь пути пользователя — вся загрузка модулей идёт через
  Support Path / `findfile`, см. `LEP-START.LSP`.
- В git идут только исходники (`.LSP`/`.DCL`/`.LIN`/`.md`) — DWG,
  lock-файлы (`.dwl`/`.dwl2`), бэкапы и выгруженные ведомости в
  `.gitignore`, не коммить их (см. `.gitignore` в корне).
- Перед добавлением новой функции проверь, нет ли уже похожей в
  `LEP-UTILS.LSP`/`LEP-POLYLINE.LSP` — в проекте уже случалось
  дублирование (`LEP:GetVertexList`/`LEP:GetVertices` делали одно и
  то же в разных файлах), и мёртвый код, который никто не вызывал.
- Комментарии в коде и описания в README — максимально подробные.
  Пользователь не программист-профессионал и сам почти не пишет
  AutoLISP, поэтому важно объяснять не только ЧТО делает код, но и
  ПОЧЕМУ именно так (особенно если решение неочевидное или это фикс
  конкретного бага) — это относится и к новым функциям, и к правкам
  существующих.

## Режим подтверждения правок

Перед любой работой сначала пиши план: что нашёл/понял и что
собираешься менять и почему. Дальше — по ситуации:

- Если правка однозначно вытекает из того, что показал сам
  пользователь (лог ошибки, скриншот, описание бага) и реального
  выбора нет — делай сразу, без паузы на подтверждение, и отчитайся,
  что сделал.
- Если есть настоящая развилка (несколько разумных вариантов
  реализации, дизайн-решение, что-то не тривиально отменить/легко
  сделать зря) — остановись и спроси, какой вариант нужен, ПЕРЕД тем
  как редактировать файлы.
