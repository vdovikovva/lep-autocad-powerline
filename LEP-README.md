# LEP — логика работы и текущее состояние проекта

Источник правды по тому, как работает программа и что в ней уже
готово. Обновляется при каждом значимом изменении. Держать в одной
папке с модулями LEP-*.LSP и открытым DWG (см. правило ниже).

## Важное правило хранения файлов

DWG чертежа должен лежать В ТОЙ ЖЕ ПАПКЕ, что и все модули
`LEP-*.LSP`. На этом держится и поиск файлов (`findfile`), и
авторегистрация папки как доверенной (`TRUSTEDPATHS`) в
`LEP-START.LSP`. Работает одинаково у любого пользователя на любой
платформе (Mac/Windows) без единой правки кода.

## Общий порядок работы

1. Открываем новый чертёж AutoCAD (сохранённый в папке с модулями).
2. Вставляем подложку — скриншот кадастровой карты (`IMAGEATTACH`).
3. `APPLOAD` → `LEP-START.LSP`.
4. `LEP-SCALE` — калибровка масштаба подложки по двум точкам с
   известным реальным расстоянием (1 ед. AutoCAD = 1 м после этого).
5. `LEP-ROUTE` — черчение маршрута (полилиния), Enter — конец
   построения. Каждый маршрут получает свой уникальный ID
   (`LEP_ROUTE_0001`, `LEP_ROUTE_0002`...) для разделения линий к
   разным заявителям в будущей ведомости. Сама полилиния маршрута
   рисуется на служебном слое `LEP-ROUTE-SERVICE` (НЕ на слое ВЛ) —
   это не настоящая линия, а "арматура" для констрейнтов опор, печать
   у неё всегда выключена. Видимость на экране — команда
   `LEP-ROUTEVIS` (включить перед кликом по маршруту в `LEP-POLE`/
   `LEP-SPAN`, выключить, чтобы не перекрывала пунктир КЛ при осмотре).
6. `LEP-POLE` — РУЧНАЯ расстановка опор в цикле:
   - клик рядом с трассой → точка проецируется на линию → вставляется
     новая вершина полилинии → опора садится туда;
   - выбор типа опоры — диалог со списком (мышкой) либо номером в
     консоли (переключается `*LEP-UseDCL*` в CONFIG);
   - выбор статуса (Проект/Сущ., по умолчанию Проект);
   - опора привязывается к вершине маршрута (`GEOMCONSTRAINT`);
   - подпись-выноска "[статус]. оп. [тип]" рядом с опорой;
   - Enter без точки - выход из цикла.
7. `LEP-SPAN` — классификация пролётов, тоже в цикле:
   - клик ПО БЛОКУ первой опоры пролёта, затем ПО БЛОКУ второй;
   - выбор типа прокладки (ВЛ/КЛ) и марки провода/кабеля (список из
     CONFIG: `*LEP-WireTypes-VL*` / `*LEP-WireTypes-KL*`);
   - создаётся отдельный объект-полилиния под этот пролёт, на своём
     слое/типе линии, с автоматической длиной и подписью;
   - ВЛ — сплошная линия слоя `LEP-PROJ-VL` (оранжевый); КЛ — свой тип
     линии `LEP_CABLE` (штамп "К" в разрывах, см. `LEP-LINETYPES.LIN`)
     слоя `LEP-PROJ-KL` (синий);
   - Enter вместо первой опоры - выход из цикла.
8. `LEP-REPORT` — выгрузка ведомости в CSV по каждому маршруту
   отдельно (пока НЕ ПЕРЕДЕЛАН, см. "Известные проблемы" ниже).

## Что уже готово и проверено

- `LEP-START` — загрузка модулей через Support Path/findfile,
  автоматическая регистрация папки в TRUSTEDPATHS (без хардкода
  пути пользователя).
- `LEP-DATA` — хранение данных объектов через XDATA (формат
  исправлен), включая `LEP:GetDataValue` для чтения по ключу.
- `LEP-ROUTE` — черчение маршрута со своим ID. Работает.
- `LEP-POLE` — ручная расстановка опор с привязкой к линии, диалог
  выбора типа, статус, подпись, защита от обрыва цикла при ошибке
  (`vl-catch-all-apply`). Проверено на тестовом блоке `test-block`.
- `LEP-SPAN` — нарезка пролётов на отдельные объекты, выбор через
  клик по блокам опор (с подсветкой при наведении), марки из
  CONFIG, автодлина и подпись. Проверено, работает (после фикса
  бага с локальными переменными `List`/`Length`, перекрывавшими
  встроенные функции AutoLISP — классическая ловушка: AutoLISP
  использует одно пространство имён для переменных и функций).
- `LEP-ROUTEVIS` — переключение видимости служебной линии маршрута
  на экране (слой `LEP-ROUTE-SERVICE`, печать которого всегда
  выключена отдельно). Работает.
- Свой тип линии `LEP_CABLE` для КЛ (файл `LEP-LINETYPES.LIN`) —
  штамп "К" в разрывах, чтобы на печати (даже ч/б) сразу было видно
  "это кабель". Загружается через `findfile`, без хардкода пути.

## Временные решения (вернуться позже)

- **Блок опоры** — сейчас используется `test-block` (кружок с
  атрибутом `TIP`, создаётся командой `LEP-MAKETESTBLOCK`), а не
  реальный `oVkILj`. Вернуться к `oVkILj`, когда решится вопрос с
  атрибутом и вариантами опор (с откосом/без).
- **Подпись опоры** — сейчас только "[статус]. оп. [тип]", без
  второй строки (класс линии/напряжение), т.к. эти данные появляются
  только после `LEP-SPAN`, уже после того как опора подписана.
  Нужно решить: оставить как есть, или добавить отдельную команду,
  дописывающую вторую строку постфактум.
- **Связь пролёта с опорами** — созданный в `LEP-SPAN` объект-пролёт
  геометрически скопирован с маршрута на момент создания, но НЕ
  связан через `GEOMCONSTRAINT` с опорами. Если подвинуть опору
  позже - основной маршрут подстроится, а нарисованный пролёт нет,
  его нужно будет создать заново.
- **Цвета ВЛ/КЛ** (`*LEP-Color-Proj-VL*` = 30 оранжевый,
  `*LEP-Color-Proj-KL*` = 5 синий, в `LEP-CONFIG.LSP`) — временные,
  подобраны на глаз для удобства на этапе проектирования. Владелец
  проекта поменяет сам после согласования с коллегой.

## Известные открытые проблемы

- `LEP-REPORT` — старая версия использует ActiveX
  (`vla-get-EffectiveName`, `vla-get-length`), которая не работает на
  Mac. Требуется переписать без ActiveX (длина - геометрически, тип
  опоры - через атрибут блока). НЕ СДЕЛАНО.
- Концовка маршрута (МТП+ЩУ / ПУ на опоре) — НЕ РЕАЛИЗОВАНА нигде.
- Марка/сечения СИП-3 для ВЛ — неизвестны, в `*LEP-WireTypes-VL*` не
  добавлены (сейчас только СИП-2 95 и 70).

## Настройки в LEP-CONFIG.LSP (актуальный список того, что должно быть)

```lisp
(setq *LEP-Block-Pole*          "test-block")  ; временно, вернуть "oVkILj" позже
(setq *LEP-Block-Pole-AttTag*   "TIP")
(setq *LEP-UseDCL*              T)              ; T = диалог, nil = ввод номером
(setq *LEP-LeaderOffset*        5.0)            ; метров, отступ подписи
(setq *LEP-Layer-Route*         "LEP-ROUTE-SERVICE")  ; служебный слой маршрута, печать выкл.
(setq *LEP-Color-Proj-VL*       30)             ; Оранжевый, временно
(setq *LEP-Color-Proj-KL*       5)              ; Синий, временно
(setq *LEP-Linetype-KL*         "LEP_CABLE")    ; из LEP-LINETYPES.LIN
(setq *LEP-LinetypeFile-KL*     "LEP-LINETYPES.LIN")
(setq *LEP-WireTypes-VL*
    (list
        (cons "СИП-2 95 мм2" "95")
        (cons "СИП-2 70 мм2" "70")
    )
)
(setq *LEP-WireTypes-KL*
    (list
        (cons "Кабель (марка неизв.) 120 мм2" "120")
    )
)
```
