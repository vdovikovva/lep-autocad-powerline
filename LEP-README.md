# LEP — логика работы и текущее состояние проекта

Источник правды по тому, как работает программа и что в ней уже
готово. Обновляется при каждом значимом изменении. Держать в одной
папке с модулями LEP-*.LSP и открытым DWG (см. правило ниже).

## Важное правило хранения файлов

DWG чертежа должен лежать В ТОЙ ЖЕ ПАПКЕ, что и все модули
`LEP-*.LSP`. На этом держится и поиск файлов (`findfile`), и
авторегистрация папки как доверенной (`TRUSTEDPATHS`) в
`LEP-START.LSP`. Работает одинаково у любого пользователя на любой
платформе (Mac/Windows) без единой правки кода.

## Общий порядок работы

1. Открываем новый чертёж AutoCAD (сохранённый в папке с модулями).
2. Вставляем подложку — скриншот кадастровой карты (`IMAGEATTACH`).
3. `APPLOAD` → `LEP-START.LSP`.
4. `LEP-SCALE` — калибровка масштаба подложки по двум точкам с
   известным реальным расстоянием (1 ед. AutoCAD = 1 м после этого).
5. `LEP-ROUTE` — черчение маршрута (полилиния), Enter — конец
   построения. Каждый маршрут получает свой уникальный ID
   (`LEP_ROUTE_01`, `LEP_ROUTE_02`...) для разделения линий к разным
   заявителям в будущей ведомости — на одном чертеже бывает несколько
   трасс. Сразу после построения у начальной точки маршрута
   появляется подпись "Маршрут NN", чтобы было видно на самом
   чертеже, какой маршрут где, а не только внутри XDATA. Сама
   полилиния маршрута рисуется на служебном слое `LEP-ROUTE-SERVICE`
   (НЕ на слое ВЛ) — это не настоящая линия, а "арматура" для
   констрейнтов опор, печать у неё всегда выключена. Видимость на
   экране — команда `LEP-ROUTEVIS` (включить перед кликом по маршруту
   в `LEP-POLE`/`LEP-SPAN`, выключить, чтобы не перекрывала пунктир КЛ
   при осмотре).
6. `LEP-POLE` — РУЧНАЯ расстановка опор в цикле:
   - клик рядом с трассой → точка проецируется на линию → вставляется
     новая вершина полилинии → опора садится туда;
   - выбор типа опоры — номером в консоли по умолчанию (можно
     переключить на диалог со списком мышкой через `*LEP-UseDCL*` в
     CONFIG, но консоль быстрее — так и оставили);
   - выбор статуса (Проект/Сущ., по умолчанию Проект) — общая функция
     `LEP:GetStatus` (в `LEP-UTILS.LSP`), используется и в `LEP-SPAN`;
   - опора привязывается к вершине маршрута (`GEOMCONSTRAINT`);
   - подпись-выноска "[статус]. оп. [тип]" рядом с опорой;
   - Enter без точки - выход из цикла.
7. `LEP-SPAN` — классификация пролётов, тоже в цикле:
   - клик ПО БЛОКУ первой опоры пролёта, затем ПО БЛОКУ второй;
   - выбор типа прокладки (ВЛ/КЛ), марки провода/кабеля (список из
     CONFIG: `*LEP-WireTypes-VL*` / `*LEP-WireTypes-KL*`) и статуса
     (Проект/Сущ., та же `LEP:GetStatus`, что и у опор);
   - создаётся отдельный объект-полилиния под этот пролёт, на своём
     слое/типе линии, с автоматической длиной и подписью
     "[статус] [марка], L=... м" (тот же формат, что у опор);
   - ВЛ — сплошная линия слоя `LEP-PROJ-VL` (оранжевый); КЛ — свой тип
     линии `LEP_CABLE` (штамп "K" в разрывах, см. `LEP-LINETYPES.LIN`)
     слоя `LEP-PROJ-KL` (синий);
   - Enter вместо первой опоры - выход из цикла.
8. `LEP-REPORT` — выгрузка ведомости в CSV. Считает только
   проектируемые (Проект.) опоры и пролёты — существующие (Сущ.) не
   нужно ни покупать, ни строить, поэтому в ведомость не попадают.
   Структура файла: сначала блок по каждой трассе отдельно (сколько
   опор по типам и метраж провода/кабеля по маркам нужно именно на
   эту линию — на одном чертеже бывает несколько трасс к разным
   заявителям), затем блок "ИТОГО" — сумма по всем трассам вместе
   (без разбивки, для закупки материалов).

## Что уже готово и проверено

- `LEP-START` — загрузка модулей через Support Path/findfile,
  автоматическая регистрация папки в TRUSTEDPATHS (без хардкода
  пути пользователя).
- `LEP-DATA` — хранение данных объектов через XDATA (формат
  исправлен), включая `LEP:GetDataValue` для чтения по ключу.
- `LEP-ROUTE` — черчение маршрута со своим ID (2 цифры, `LEP_ROUTE_01`),
  автоподпись "Маршрут NN" у начальной точки. Работает.
- `LEP-POLE` — ручная расстановка опор с привязкой к линии, диалог
  выбора типа, статус, подпись, защита от обрыва цикла при ошибке
  (`vl-catch-all-apply`). Проверено на тестовом блоке `test-block`.
- `LEP-SPAN` — нарезка пролётов на отдельные объекты, выбор через
  клик по блокам опор (с подсветкой при наведении), марки из
  CONFIG, статус (Проект/Сущ.), автодлина и подпись. Проверено,
  работает (после фикса бага с локальными переменными
  `List`/`Length`, перекрывавшими встроенные функции AutoLISP —
  классическая ловушка: AutoLISP использует одно пространство имён
  для переменных и функций).
- `LEP-ROUTEVIS` — переключение видимости служебной линии маршрута
  на экране (слой `LEP-ROUTE-SERVICE`, печать которого всегда
  выключена отдельно). Проверено, работает.
- Свой тип линии `LEP_CABLE` для КЛ (файл `LEP-LINETYPES.LIN`) —
  штамп "K" (латиница, не кириллица — см. "Временные решения") в
  разрывах, чтобы на печати (даже ч/б) сразу было видно "это кабель".
  Загружается через `findfile`, без хардкода пути.
- `LEP:GetStatus` (`LEP-UTILS.LSP`) — общий запрос статуса
  (Проект/Сущ.) для опор и пролётов, чтобы не дублировать одну и ту
  же логику в двух модулях.
- `LEP:ChooseFromList` (`LEP-UTILS.LSP`) — общее номерное меню выбора
  из списка (каждый пункт на своей строке), для марки провода/типа
  прокладки в `LEP-SPAN` и для типа опоры в `LEP-POLE`.
- `LEP-REPORT` — переписан без ActiveX (`vl-load-com`, `vla-get-length`,
  `vla-get-EffectiveName` убраны — не работали на Mac). Длина и тип
  опоры теперь берутся из уже готовой XDATA, а не пересчитываются.
  Пролёты (`LEP-SPAN`) теперь тоже пишут в XDATA `ROUTE` (ID трассы,
  которой раньше у них не было) — без этого ведомость не смогла бы
  сгруппировать метраж провода/кабеля по трассам. Трассы в CSV идут
  по порядку номеров (1, 2, 3...) — `ssget "_X"` отдаёт объекты не в
  порядке создания, список сортируется по `RouteID` перед записью
  (`vl-sort`). Название трассы —
  строкой-заголовком над блоком материалов (не в каждой строке). CSV
  пишется в настоящем UTF-8 — ключ оказался в третьем (необязательном)
  аргументе `open`: `(open path "w" "utf8-bom")` (появился в AutoCAD
  2021). Без него `open` по умолчанию использует старую однобайтовую
  кодировку (Windows-1251 для кириллицы) — самодельные попытки
  закодировать байты вручную через `write-char` были лишними, дело
  было не в `write-char`, а в режиме открытия файла. Вариант именно
  `"utf8-bom"` (а не просто `"utf8"`) нужен из-за Excel — он умеет
  правильно определять UTF-8 только по метке BOM в начале файла,
  другие программы (Sublime, Notes, Quick Look) открывали верно и без
  неё. Если чертёж сохранён не в папке с модулями — команда честно
  предупреждает об
  этом (путь строится от `DWGPREFIX`, т.е. от папки ТЕКУЩЕГО
  сохранения чертежа), но автоматически чертёж не сохраняет.

## Временные решения (вернуться позже)

- **Блок опоры** — сейчас используется `test-block` (кружок с
  атрибутом `TIP`, создаётся командой `LEP-MAKETESTBLOCK`), а не
  реальный `oVkILj`. Вернуться к `oVkILj`, когда решится вопрос с
  атрибутом и вариантами опор (с откосом/без).
- **Подпись опоры** — сейчас только "[статус]. оп. [тип]", без
  второй строки (класс линии/напряжение), т.к. эти данные появляются
  только после `LEP-SPAN`, уже после того как опора подписана.
  Нужно решить: оставить как есть, или добавить отдельную команду,
  дописывающую вторую строку постфактум.
- **Связь пролёта с опорами** — созданный в `LEP-SPAN` объект-пролёт
  геометрически скопирован с маршрута на момент создания, но НЕ
  связан через `GEOMCONSTRAINT` с опорами. Если подвинуть опору
  позже - основной маршрут подстроится, а нарисованный пролёт нет,
  его нужно будет создать заново.
- **Цвета ВЛ/КЛ** (`*LEP-Color-Proj-VL*` = 30 оранжевый,
  `*LEP-Color-Proj-KL*` = 5 синий, в `LEP-CONFIG.LSP`) — временные,
  подобраны на глаз для удобства на этапе проектирования. Владелец
  проекта поменяет сам после согласования с коллегой.
- **Буква "K" в типе линии `LEP_CABLE`** — латиница, не кириллица.
  Визуально не отличить, а кириллица в `.LIN`-файле (UTF-8) ломает
  разбор у классического парсера типов линий AutoCAD (читает файл
  как однобайтовую ANSI-кодировку). Не менять на "К" без проверки,
  что кодировка файла это переживёт.

## Известные открытые проблемы

- Концовка маршрута (МТП+ЩУ / ПУ на опоре) — НЕ РЕАЛИЗОВАНА нигде, и
  расставить их на чертеже пока нечем, поэтому в `LEP-REPORT` их тоже
  пока нет (не потому что блоки не готовы, а потому что таких
  объектов ещё физически не бывает в DWG). Вернуться к этому после
  того, как блоки опор/МТП/РЛК/ПУ будут готовы.
- Марка/сечения СИП-3 для ВЛ — неизвестны, в `*LEP-WireTypes-VL*` не
  добавлены (сейчас только СИП-2 95 и 70).
## Настройки в LEP-CONFIG.LSP (актуальный список того, что должно быть)

```lisp
(setq *LEP-Block-Pole*          "test-block")  ; временно, вернуть "oVkILj" позже
(setq *LEP-Block-Pole-AttTag*   "TIP")
(setq *LEP-UseDCL*              nil)            ; T = диалог, nil = ввод номером (быстрее, по умолчанию)
(setq *LEP-LeaderOffset*        5.0)            ; метров, отступ подписи
(setq *LEP-Layer-Route*         "LEP-ROUTE-SERVICE")  ; служебный слой маршрута, печать выкл.
(setq *LEP-Color-Proj-VL*       30)             ; Оранжевый, временно
(setq *LEP-Color-Proj-KL*       5)              ; Синий, временно
(setq *LEP-Linetype-KL*         "LEP_CABLE")    ; из LEP-LINETYPES.LIN
(setq *LEP-LinetypeFile-KL*     "LEP-LINETYPES.LIN")
(setq *LEP-WireTypes-VL*
    (list
        (cons "СИП-2 95 мм2" "95")
        (cons "СИП-2 70 мм2" "70")
    )
)
(setq *LEP-WireTypes-KL*
    (list
        (cons "Кабель (марка неизв.) 120 мм2" "120")
    )
)
```
